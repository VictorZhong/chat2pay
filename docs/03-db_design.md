# chat2pay - Database Design

## 1. Overview

This document defines the PostgreSQL persistence design for the chat2pay POC.

### Persistence Goals
- persist POC profiles
- persist chat sessions and chat history
- persist one active transfer draft per chat session
- persist workflow transition history for debugging and replay
- support session reopening and history viewing

### Storage Principles
- PostgreSQL as the only persistent store for the POC
- structured assistant blocks and proposal summaries stored as `jsonb`
- identifiers generated by the application as **ULIDs** (`varchar(26)`)
- timestamps stored as `timestamptz`
- soft business states represented with constrained `varchar` columns and check constraints

## 3. Table Design

## 3.1 `poc_profile`

Stores the predefined mock profiles shown on the landing page.

### Key Notes
- small and static for the POC
- can be seeded by Flyway
- acts as the trusted source for pseudo-login

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `profile_code` | `varchar(64)` | Human-readable internal code |
| `username` | `varchar(128)` | Displayed in the sidebar footer |
| `display_name` | `varchar(128)` | Full display name |
| `avatar_url` | `varchar(256)` | Optional image URL |
| `mock_customer_id` | `varchar(64)` | Used by downstream API adapters |
| `locale` | `varchar(16)` | Example `en-HK` |
| `status` | `varchar(16)` | `ACTIVE` / `INACTIVE` |

---

## 3.2 `chat_session`

Represents one conversation thread.

### Key Notes
- one row per visible chat in the left history list
- a session can be active, completed, cancelled, or archived
- `active_draft_id` points to the currently active transaction draft if one exists
- `workflow_state` keeps the latest state for quick list rendering without joining message history

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `profile_id` | `varchar(26)` | FK to `poc_profile.id` |
| `title` | `varchar(160)` | Session title shown in the sidebar |
| `status` | `varchar(32)` | Session status |
| `workflow_state` | `varchar(32)` | Latest state snapshot |
| `active_draft_id` | `varchar(26)` | Optional FK to `transaction_draft.id` |
| `message_count` | `int` | Denormalized for list performance |
| `created_at` | `timestamptz` | Creation time |
| `updated_at` | `timestamptz` | Last activity time |
| `archived_at` | `timestamptz` | Set when archived |

---

## 3.3 `chat_message`

Stores user and assistant messages in sequence order.

### Key Notes
- one logical message per row
- text-only messages can use `content_text`
- structured assistant blocks are stored in `content_blocks_json`
- UI interactions can be persisted as `message_type = UI_EVENT`
- `sequence_no` is monotonically increasing within a session

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `session_id` | `varchar(26)` | FK to `chat_session.id` |
| `sequence_no` | `int` | Ordered message number within the session |
| `role` | `varchar(16)` | `USER`, `ASSISTANT`, `SYSTEM` |
| `message_type` | `varchar(24)` | `TEXT`, `CARD`, `LIST`, `FORM`, `UI_EVENT` |
| `input_source` | `varchar(24)` | `TEXT`, `LIST_SELECTION`, `FORM_SUBMISSION`, `SYSTEM` |
| `content_text` | `text` | Raw or canonical text |
| `content_blocks_json` | `jsonb` | Structured blocks returned to the frontend |
| `structured_payload_json` | `jsonb` | Raw event payload or auxiliary metadata |
| `created_at` | `timestamptz` | Message timestamp |

---

## 3.4 `transaction_draft`

Represents the in-progress or completed transfer payload associated with a chat session.

### Key Notes
- one active draft per session in the POC
- supports reconstruction of the transfer summary without replaying every message
- stores downstream references such as `proposal_id` and `transfer_reference`
- flexible fields such as `proposal_summary_json` and `additional_context_json` remain in JSONB for POC agility

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `session_id` | `varchar(26)` | Unique FK to `chat_session.id` |
| `status` | `varchar(32)` | `DRAFT`, `PROPOSED`, `CONFIRMED`, `FAILED`, `CANCELLED` |
| `workflow_state` | `varchar(48)` | Mirrors the latest workflow state |
| `source_account_id` | `varchar(64)` | Downstream account ID |
| `source_account_display` | `varchar(160)` | UI-friendly label |
| `payee_id` | `varchar(64)` | Downstream payee ID |
| `payee_display` | `varchar(160)` | UI-friendly label |
| `amount` | `numeric(18,2)` | Transfer amount |
| `currency` | `varchar(3)` | ISO currency code |
| `payment_rail` | `varchar(16)` | `GDLV`, `GDRIA`, `ORTT` |
| `note` | `varchar(280)` | Optional note or remark |
| `limit_check_status` | `varchar(24)` | `NOT_STARTED`, `PASSED`, `FAILED` |
| `proposal_id` | `varchar(64)` | Returned by propose API |
| `proposal_summary_json` | `jsonb` | Fee / quote / transfer summary |
| `transfer_reference` | `varchar(64)` | Returned by confirm API |
| `additional_context_json` | `jsonb` | Free-form contextual details |
| `created_at` | `timestamptz` | Draft creation time |
| `updated_at` | `timestamptz` | Last update |
| `completed_at` | `timestamptz` | Set on completion |

---

## 3.5 `workflow_transition_log`

Immutable event log for every meaningful workflow transition.

### Key Notes
- useful for debugging, replay, observability, and audit-style troubleshooting
- not a substitute for full event sourcing; it is a diagnostics log for the POC
- multiple rows can be written for the same session and draft

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `bigserial` | Surrogate primary key |
| `session_id` | `varchar(26)` | FK to `chat_session.id` |
| `draft_id` | `varchar(26)` | FK to `transaction_draft.id`, nullable for early events |
| `from_state` | `varchar(48)` | Previous workflow state |
| `to_state` | `varchar(48)` | New workflow state |
| `event_name` | `varchar(48)` | Domain event |
| `action_name` | `varchar(48)` | Triggered action |
| `result_status` | `varchar(24)` | `SUCCESS`, `FAILED`, `SKIPPED` |
| `detail_json` | `jsonb` | Error info or action details |
| `created_at` | `timestamptz` | Event timestamp |

## 4. Indexing Strategy

### `poc_profile`
- unique index on `profile_code`
- index on `status`

### `chat_session`
- index on `profile_id, updated_at desc`
- index on `profile_id, status, updated_at desc`
- index on `active_draft_id`

### `chat_message`
- unique index on `session_id, sequence_no`
- index on `session_id, created_at`
- index on `session_id, role`

### `transaction_draft`
- unique index on `session_id`
- index on `status`
- index on `workflow_state`
- index on `proposal_id`
- index on `transfer_reference`

### `workflow_transition_log`
- index on `session_id, created_at desc`
- index on `draft_id, created_at desc`
- index on `event_name, created_at desc`

## 5. DDL

```sql
create table if not exists poc_profile (
    id varchar(26) primary key,
    profile_code varchar(64) not null unique,
    username varchar(128) not null,
    display_name varchar(128) not null,
    avatar_url varchar(256),
    mock_customer_id varchar(64) not null,
    locale varchar(16) not null default 'en-HK',
    status varchar(16) not null,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    constraint ck_poc_profile_status
        check (status in ('ACTIVE', 'INACTIVE'))
);

create table if not exists chat_session (
    id varchar(26) primary key,
    profile_id varchar(26) not null,
    title varchar(160) not null,
    status varchar(32) not null,
    workflow_state varchar(32) not null,
    active_draft_id varchar(26),
    message_count integer not null default 0,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    archived_at timestamptz null,
    constraint fk_chat_session_profile
        foreign key (profile_id) references poc_profile(id),
    constraint ck_chat_session_status
        check (status in ('ACTIVE', 'COMPLETED', 'CANCELLED', 'ARCHIVED')),
    constraint ck_chat_session_workflow_state
        check (workflow_state in (
            'IDLE',
            'COLLECTING_TRANSFER_INFO',
            'RESOLVING_AMBIGUITY',
            'READY_FOR_PAYMENT_OPTIONS',
            'READY_FOR_LIMIT_CHECK',
            'READY_FOR_PROPOSE',
            'AWAITING_USER_CONFIRMATION',
            'READY_FOR_CONFIRM',
            'COMPLETED',
            'FAILED',
            'CANCELLED'
        ))
);

create table if not exists transaction_draft (
    id varchar(26) primary key,
    session_id varchar(26) not null unique,
    status varchar(32) not null,
    workflow_state varchar(48) not null,
    source_account_id varchar(64),
    source_account_display varchar(160),
    payee_id varchar(64),
    payee_display varchar(160),
    amount numeric(18,2),
    currency varchar(3),
    payment_rail varchar(16),
    note varchar(280),
    limit_check_status varchar(24),
    proposal_id varchar(64),
    proposal_summary_json jsonb,
    transfer_reference varchar(64),
    additional_context_json jsonb,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    completed_at timestamptz null,
    constraint fk_transaction_draft_session
        foreign key (session_id) references chat_session(id),
    constraint ck_transaction_draft_status
        check (status in ('DRAFT', 'PROPOSED', 'CONFIRMED', 'FAILED', 'CANCELLED')),
    constraint ck_transaction_draft_workflow_state
        check (workflow_state in (
            'IDLE',
            'COLLECTING_TRANSFER_INFO',
            'RESOLVING_AMBIGUITY',
            'READY_FOR_PAYMENT_OPTIONS',
            'READY_FOR_LIMIT_CHECK',
            'READY_FOR_PROPOSE',
            'AWAITING_USER_CONFIRMATION',
            'READY_FOR_CONFIRM',
            'COMPLETED',
            'FAILED',
            'CANCELLED'
        )),
    constraint ck_transaction_draft_payment_rail
        check (payment_rail is null or payment_rail in ('GDLV', 'GDRIA', 'ORTT')),
    constraint ck_transaction_draft_limit_check_status
        check (limit_check_status is null or limit_check_status in ('NOT_STARTED', 'PASSED', 'FAILED'))
);

alter table chat_session
    add constraint fk_chat_session_active_draft
    foreign key (active_draft_id) references transaction_draft(id);

create table if not exists chat_message (
    id varchar(26) primary key,
    session_id varchar(26) not null,
    sequence_no integer not null,
    role varchar(16) not null,
    message_type varchar(24) not null,
    input_source varchar(24) not null,
    content_text text,
    content_blocks_json jsonb,
    structured_payload_json jsonb,
    created_at timestamptz not null default now(),
    constraint fk_chat_message_session
        foreign key (session_id) references chat_session(id),
    constraint uq_chat_message_session_seq unique (session_id, sequence_no),
    constraint ck_chat_message_role
        check (role in ('USER', 'ASSISTANT', 'SYSTEM')),
    constraint ck_chat_message_type
        check (message_type in ('TEXT', 'CARD', 'LIST', 'FORM', 'UI_EVENT')),
    constraint ck_chat_message_input_source
        check (input_source in ('TEXT', 'LIST_SELECTION', 'FORM_SUBMISSION', 'SYSTEM'))
);

create table if not exists workflow_transition_log (
    id bigserial primary key,
    session_id varchar(26) not null,
    draft_id varchar(26),
    from_state varchar(48),
    to_state varchar(48) not null,
    event_name varchar(48) not null,
    action_name varchar(48),
    result_status varchar(24) not null,
    detail_json jsonb,
    created_at timestamptz not null default now(),
    constraint fk_workflow_transition_log_session
        foreign key (session_id) references chat_session(id),
    constraint fk_workflow_transition_log_draft
        foreign key (draft_id) references transaction_draft(id),
    constraint ck_workflow_transition_log_result_status
        check (result_status in ('SUCCESS', 'FAILED', 'SKIPPED'))
);

create index if not exists idx_poc_profile_status
    on poc_profile(status);

create index if not exists idx_chat_session_profile_updated
    on chat_session(profile_id, updated_at desc);

create index if not exists idx_chat_session_profile_status_updated
    on chat_session(profile_id, status, updated_at desc);

create index if not exists idx_chat_session_active_draft
    on chat_session(active_draft_id);

create index if not exists idx_chat_message_session_created
    on chat_message(session_id, created_at);

create index if not exists idx_chat_message_session_role
    on chat_message(session_id, role);

create index if not exists idx_transaction_draft_status
    on transaction_draft(status);

create index if not exists idx_transaction_draft_workflow_state
    on transaction_draft(workflow_state);

create index if not exists idx_transaction_draft_proposal_id
    on transaction_draft(proposal_id);

create index if not exists idx_transaction_draft_transfer_reference
    on transaction_draft(transfer_reference);

create index if not exists idx_workflow_transition_log_session_created
    on workflow_transition_log(session_id, created_at desc);

create index if not exists idx_workflow_transition_log_draft_created
    on workflow_transition_log(draft_id, created_at desc);

create index if not exists idx_workflow_transition_log_event_created
    on workflow_transition_log(event_name, created_at desc);
```

## 6. Seed Data Guidance

For the POC, seed `poc_profile` using Flyway or equivalent with 4–5 fixed rows, for example:
- HK retail customer profile
- HK premier customer profile
- SG retail customer profile
- staff demo profile A
- staff demo profile B

This allows the landing page to present stable selectable identities without any authentication dependency.

## 7. Operational Notes

- `updated_at` should be refreshed by the application on every meaningful change.
- Message insertion should increment `sequence_no` inside the transaction that writes the message.
- `proposal_summary_json` should store a normalized summary shape, not a raw downstream payload dump.
- `structured_payload_json` should capture enough data to reconstruct list or form interactions for replay.
- If a session is reopened and no active draft exists, `chat_session.active_draft_id` should remain null.
