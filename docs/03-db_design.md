# chat2pay - Database Design

## 1. Overview

This document defines the PostgreSQL persistence design for the chat2pay POC.

### Persistence Goals

- persist POC profiles returned to the landing page
- persist chat sessions and message history
- persist one active payment draft per session
- persist workflow transitions for troubleshooting and replay
- keep the current POC simple while allowing future payment journeys to store
  additional orchestration data

### Storage Principles

- PostgreSQL is the only persistent store for the POC
- chat session, message, and draft identifiers are generated by the application
  as ULIDs (`varchar(26)`)
- demo profile identifiers are stored as `varchar(64)` so seeded or manually
  inserted profile keys are not forced to be ULIDs
- timestamps use `timestamptz`
- structured assistant blocks are stored as `jsonb`
- journey-specific integration details use JSONB rather than hardcoding every
  future downstream field into the first schema version
- do not create one new table per downstream API by default; prefer storing
  journey-local tool references and summaries in existing draft JSON first
- all application tables use the `ctp_` prefix
- Flyway schema history is stored in `ctp_flyway_schema_history`

## 3. Table Design

## 3.1 `ctp_profile`

Stores the predefined demo profiles shown on the landing page.

### Key Notes

- current POC can seed only one active profile row
- later the user can add more rows in DB without changing the frontend shell
- `username` is the downstream `payment10` identity and is the most important
  integration field
- display-oriented fields can stay lightweight and demo-friendly

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(64)` | Stable profile key; not required to be a ULID |
| `profile_code` | `varchar(64)` | Human-readable internal code |
| `username` | `varchar(128)` | Downstream `payment10` value |
| `display_name` | `varchar(128)` | Full display name shown in UI |
| `avatar_url` | `varchar(256)` | Optional image URL |
| `mock_customer_id` | `varchar(64)` | Demo-only customer label for UI |
| `locale` | `varchar(16)` | Example `en-HK` |
| `supported_journey_types_json` | `jsonb` | Example `["DOMESTIC_EXISTING_PAYEE"]` |
| `status` | `varchar(16)` | `ACTIVE` / `INACTIVE` |

## 3.2 `ctp_chat_session`

Represents one conversation thread.

### Key Notes

- one row per visible chat in the left history rail
- `journey_type` is nullable until the first supported payment journey is
  recognized
- `workflow_state` is kept on the session for quick rendering without joining
  every message

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `profile_id` | `varchar(64)` | FK to `ctp_profile.id` |
| `title` | `varchar(160)` | Session title shown in the sidebar |
| `status` | `varchar(32)` | `ACTIVE`, `COMPLETED`, `CANCELLED`, `ARCHIVED` |
| `workflow_state` | `varchar(48)` | Latest high-level state snapshot |
| `journey_type` | `varchar(48)` | Current payment journey, nullable initially |
| `message_count` | `int` | Denormalized for list rendering |
| `created_at` | `timestamptz` | Creation time |
| `updated_at` | `timestamptz` | Last activity time |

---

## 3.3 `ctp_chat_message`

Stores user and assistant messages in sequence order.

### Key Notes

- one logical message per row
- assistant blocks are stored in `content_blocks_json`
- the persisted block JSON explicitly stores block `type` so messages can be
  rehydrated without frontend participation

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `session_id` | `varchar(26)` | FK to `ctp_chat_session.id` |
| `sequence_no` | `int` | Ordered message number within the session |
| `role` | `varchar(16)` | `USER`, `ASSISTANT`, `SYSTEM` |
| `message_type` | `varchar(24)` | `TEXT`, `CARD`, `LIST`, `FORM`, `UI_EVENT` |
| `content_text` | `text` | Raw or canonical text |
| `content_blocks_json` | `jsonb` | Structured blocks returned to the frontend |
| `created_at` | `timestamptz` | Message timestamp |

---

## 3.4 `ctp_payment_draft`

Represents the in-progress or completed payment payload associated with a chat
session.

### Key Notes

- one active draft per session in the POC
- current domestic flow must persist `payee_name_input`, `payee_id_index`, and
  `payee_type` because those values are required by the confirm step described
  in `docs/11-backend-skill.md`
- `review_summary_json` stores the normalized summary shown to the user before
  confirmation
- `downstream_references_json` keeps journey-specific references flexible for
  future international and multi-step flows such as limit checks, fraud checks,
  FX quotes, and review references
- `candidate_payees_json` stores temporary payee options so ambiguous selection
  and "change payee" flows survive app restarts

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `varchar(26)` | ULID primary key |
| `session_id` | `varchar(26)` | Unique FK to `ctp_chat_session.id` |
| `journey_type` | `varchar(48)` | Example `DOMESTIC_EXISTING_PAYEE` |
| `status` | `varchar(32)` | `DRAFT`, `READY_FOR_CONFIRMATION`, `CONFIRMING`, `CONFIRMED`, `FAILED`, `CANCELLED` |
| `workflow_state` | `varchar(48)` | Mirrors latest workflow state |
| `source_account_id` | `varchar(64)` | Downstream account ID or alias |
| `source_account_display` | `varchar(160)` | UI-friendly account label |
| `payee_name_input` | `varchar(160)` | Raw or normalized user payee input |
| `payee_id_index` | `varchar(128)` | Downstream payee identifier from payee list |
| `payee_type` | `varchar(32)` | Downstream payee type |
| `payee_display` | `varchar(160)` | UI-friendly confirmed payee name |
| `amount` | `numeric(18,2)` | Transfer amount |
| `currency` | `varchar(3)` | ISO currency code, currently expected `HKD` |
| `note` | `varchar(280)` | Optional note or memo |
| `review_summary_json` | `jsonb` | Data rendered to the user before confirm |
| `downstream_references_json` | `jsonb` | Flexible place for future quote / limit / check references |
| `transfer_reference` | `varchar(128)` | Final downstream transfer reference |
| `additional_context_json` | `jsonb` | Free-form journey context |
| `candidate_payees_json` | `jsonb` | Temporary registered payee options for disambiguation |
| `created_at` | `timestamptz` | Draft creation time |
| `updated_at` | `timestamptz` | Last update |

---

## 3.5 `ctp_workflow_transition_log`

Immutable diagnostics log for meaningful workflow transitions.

### Key Notes

- useful for debugging and replay
- not full event sourcing
- `detail_json` should capture downstream response summaries and important
  orchestration decisions

### Important Columns

| Column | Type | Notes |
|---|---|---|
| `id` | `bigserial` | Surrogate primary key |
| `session_id` | `varchar(26)` | FK to `chat_session.id` |
| `draft_id` | `varchar(26)` | FK to `transaction_draft.id`, nullable early on |
| `from_state` | `varchar(48)` | Previous workflow state |
| `to_state` | `varchar(48)` | New workflow state |
| `event_name` | `varchar(48)` | Domain event |
| `action_name` | `varchar(48)` | Triggered action |
| `result_status` | `varchar(24)` | `SUCCESS`, `FAILED`, `SKIPPED` |
| `detail_json` | `jsonb` | Error info or action details |
| `created_at` | `timestamptz` | Event timestamp |

## 4. Indexing Strategy

### `poc_profile`

- unique index on `profile_code`
- unique index on `username`
- index on `status`

### `chat_session`

- index on `profile_id, updated_at desc`
- index on `profile_id, status, updated_at desc`
- index on `journey_type`
- index on `active_draft_id`

### `chat_message`

- unique index on `session_id, sequence_no`
- index on `session_id, created_at`
- index on `session_id, role`

### `transaction_draft`

- unique index on `session_id`
- index on `journey_type`
- index on `status`
- index on `workflow_state`
- index on `payee_id_index`
- index on `transfer_reference`

### `workflow_transition_log`

- index on `session_id, created_at desc`
- index on `draft_id, created_at desc`
- index on `event_name, created_at desc`

## 5. DDL

```sql
create table if not exists poc_profile (
    id varchar(26) primary key,
    profile_code varchar(64) not null unique,
    username varchar(128) not null unique,
    display_name varchar(128) not null,
    avatar_url varchar(256),
    mock_customer_id varchar(64) not null,
    locale varchar(16) not null default 'en-HK',
    supported_journey_types_json jsonb not null default '[]'::jsonb,
    status varchar(16) not null,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    constraint ck_poc_profile_status
        check (status in ('ACTIVE', 'INACTIVE'))
);

create table if not exists chat_session (
    id varchar(26) primary key,
    profile_id varchar(26) not null,
    title varchar(160) not null,
    status varchar(32) not null,
    workflow_state varchar(48) not null,
    journey_type varchar(48),
    active_draft_id varchar(26),
    message_count integer not null default 0,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    archived_at timestamptz null,
    constraint fk_chat_session_profile
        foreign key (profile_id) references poc_profile(id),
    constraint ck_chat_session_status
        check (status in ('ACTIVE', 'COMPLETED', 'CANCELLED', 'ARCHIVED')),
    constraint ck_chat_session_workflow_state
        check (workflow_state in (
            'IDLE',
            'COLLECTING_PAYMENT_DETAILS',
            'RESOLVING_PAYEE',
            'AWAITING_USER_CONFIRMATION',
            'CONFIRMING_PAYMENT',
            'COMPLETED',
            'FAILED',
            'CANCELLED'
        )),
    constraint ck_chat_session_journey_type
        check (journey_type is null or journey_type in (
            'DOMESTIC_EXISTING_PAYEE',
            'DOMESTIC_NEW_PAYEE',
            'INTERNATIONAL_EXISTING_PAYEE',
            'INTERNATIONAL_NEW_PAYEE'
        ))
);

create table if not exists transaction_draft (
    id varchar(26) primary key,
    session_id varchar(26) not null unique,
    journey_type varchar(48) not null,
    status varchar(32) not null,
    workflow_state varchar(48) not null,
    source_account_id varchar(64),
    source_account_display varchar(160),
    payee_name_input varchar(160),
    payee_id_index varchar(128),
    payee_type varchar(32),
    payee_display varchar(160),
    amount numeric(18,2),
    currency varchar(3),
    note varchar(280),
    review_summary_json jsonb,
    downstream_references_json jsonb,
    transfer_reference varchar(128),
    additional_context_json jsonb,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    completed_at timestamptz null,
    constraint fk_transaction_draft_session
        foreign key (session_id) references chat_session(id),
    constraint ck_transaction_draft_journey_type
        check (journey_type in (
            'DOMESTIC_EXISTING_PAYEE',
            'DOMESTIC_NEW_PAYEE',
            'INTERNATIONAL_EXISTING_PAYEE',
            'INTERNATIONAL_NEW_PAYEE'
        )),
    constraint ck_transaction_draft_status
        check (status in (
            'DRAFT',
            'READY_FOR_CONFIRMATION',
            'CONFIRMING',
            'CONFIRMED',
            'FAILED',
            'CANCELLED'
        )),
    constraint ck_transaction_draft_workflow_state
        check (workflow_state in (
            'IDLE',
            'COLLECTING_PAYMENT_DETAILS',
            'RESOLVING_PAYEE',
            'AWAITING_USER_CONFIRMATION',
            'CONFIRMING_PAYMENT',
            'COMPLETED',
            'FAILED',
            'CANCELLED'
        ))
);

alter table chat_session
    add constraint fk_chat_session_active_draft
    foreign key (active_draft_id) references transaction_draft(id);

create table if not exists chat_message (
    id varchar(26) primary key,
    session_id varchar(26) not null,
    sequence_no integer not null,
    role varchar(16) not null,
    message_type varchar(24) not null,
    input_source varchar(24) not null,
    content_text text,
    content_blocks_json jsonb,
    structured_payload_json jsonb,
    created_at timestamptz not null default now(),
    constraint fk_chat_message_session
        foreign key (session_id) references chat_session(id),
    constraint uq_chat_message_session_seq unique (session_id, sequence_no),
    constraint ck_chat_message_role
        check (role in ('USER', 'ASSISTANT', 'SYSTEM')),
    constraint ck_chat_message_type
        check (message_type in ('TEXT', 'CARD', 'LIST', 'FORM', 'UI_EVENT')),
    constraint ck_chat_message_input_source
        check (input_source in ('TEXT', 'LIST_SELECTION', 'FORM_SUBMISSION', 'SYSTEM'))
);

create table if not exists workflow_transition_log (
    id bigserial primary key,
    session_id varchar(26) not null,
    draft_id varchar(26),
    from_state varchar(48),
    to_state varchar(48) not null,
    event_name varchar(48) not null,
    action_name varchar(48),
    result_status varchar(24) not null,
    detail_json jsonb,
    created_at timestamptz not null default now(),

    constraint fk_workflow_transition_log_draft
        foreign key (draft_id) references transaction_draft(id),
    constraint ck_workflow_transition_log_result_status

create index if not exists idx_poc_profile_status
    on poc_profile(status);

create index if not exists idx_chat_session_profile_updated
    on chat_session(profile_id, updated_at desc);

create index if not exists idx_chat_session_profile_status_updated
    on chat_session(profile_id, status, updated_at desc);

create index if not exists idx_chat_session_journey_type
    on chat_session(journey_type);

create index if not exists idx_chat_session_active_draft
    on chat_session(active_draft_id);

create index if not exists idx_chat_message_session_created
    on chat_message(session_id, created_at);

create index if not exists idx_chat_message_session_role
    on chat_message(session_id, role);

create index if not exists idx_transaction_draft_journey_type
    on transaction_draft(journey_type);

create index if not exists idx_transaction_draft_status
    on transaction_draft(status);

create index if not exists idx_transaction_draft_workflow_state
    on transaction_draft(workflow_state);

create index if not exists idx_transaction_draft_payee_id_index
    on transaction_draft(payee_id_index);

create index if not exists idx_transaction_draft_transfer_reference
    on transaction_draft(transfer_reference);

create index if not exists idx_workflow_transition_log_session_created
    on workflow_transition_log(session_id, created_at desc);

create index if not exists idx_workflow_transition_log_draft_created
    on workflow_transition_log(draft_id, created_at desc);

```

## 6. Seed Data Guidance

For the first POC:

- seed one `ACTIVE` profile row
- set `username` to the downstream `payment10` value
- keep `supported_journey_types_json` as `["DOMESTIC_EXISTING_PAYEE"]`
- use lightweight demo values for `display_name`, `avatar_url`, and
  `mock_customer_id`

More profiles can be added later without changing the frontend structure.

## 7. Operational Notes

- refresh `updated_at` on every meaningful change
- insert messages and update `sequence_no` in the same transaction
- persist the normalized confirmation card payload in `review_summary_json`
- store raw or summarized downstream identifiers in `downstream_references_json`
- keep `detail_json` in `workflow_transition_log` concise but diagnostic

## 8. Future Journey Extension Guidance

When adding a new journey such as an international payment:

- reuse `ctp_chat_session`, `ctp_chat_message`, and `ctp_payment_draft` first
- extend `journey_type` constraints in a new Flyway migration if a new enum
  value is introduced
- persist downstream tool references in `downstream_references_json`
- persist planner-visible journey state in `additional_context_json`
- add new typed columns only when the value is needed for:
  - cross-journey querying
  - reconciliation or audit exports
  - indexing / filtering
  - non-optional downstream confirm payloads used by multiple journeys

Recommended JSON shape for multi-step journeys:

```json
{
  "downstreamReferences": {
    "limitCheck": {
      "referenceId": "limit-001",
      "status": "PASSED"
    },
    "fraudCheck": {
      "referenceId": "fraud-001",
      "status": "CLEARED"
    },
    "fxQuote": {
      "quoteId": "fx-001",
      "sellCurrency": "HKD",
      "buyCurrency": "USD",
      "expiresAt": "2026-04-17T12:30:00Z"
    }
  },
  "additionalContext": {
    "journeyStepKey": "FX_QUOTED",
    "requiredUserInputs": ["purposeOfPayment"],
    "completedChecks": ["limitCheck", "fraudCheck"]
  }
}
```

Recommended rule:

- keep JSON keys namespaced by capability such as `limitCheck`, `fraudCheck`,
  `fxQuote`, `beneficiaryValidation`
- store summaries, statuses, and references, not full raw downstream payloads
- if a downstream result is large or sensitive, persist only the subset needed
  to continue the journey and troubleshoot failures
